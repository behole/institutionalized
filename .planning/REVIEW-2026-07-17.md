# Repo Review — 2026-07-17

External review of the repo's intent and execution. Two parts:
**A.** What would have been done differently building this from scratch (conceptual deltas).
**B.** Concrete punch list to make the repo awesome (ordered by leverage).

## Intent (as understood)

Encode centuries-old human decision institutions (courtrooms, peer review, red teams,
Delphi, tumor boards…) as multi-agent LLM orchestration patterns — 26 frameworks behind
one CLI + one MCP server, with audit trails, cost tracking, and multi-provider support.
The pitch: **structured adversarial/collaborative deliberation beats single-shot prompting
for high-stakes decisions.**

**What's genuinely well done:** consistent framework shape; real shared core
(semaphore-gated parallelism, retry, circuit breaker, sanitize, Zod, MockProvider,
fast-check property tests); 26 mock integration suites + API-key-gated e2e; per-framework
READMEs; CI, lint-staged. Far past toy quality.

---

## A. What I'd do differently from scratch

### 1. Prove the central claim before building framework #6

The product's entire premise — "institutional patterns produce _better decisions_" — is
asserted, nowhere tested. ARCHITECTURE.md describes the right thing ("Accuracy Tests:
compare framework decisions to human expert panels") and it was never built;
`benchmark/` only measures execution time and memory. 26 instruments, zero calibration.
Correct order: **3 frameworks + an eval harness with ground-truth cases**, publish
"courtroom vs single call: +X% on merge/no-merge decisions", _then_ scale the catalog.
Breadth became the headline ("26 frameworks!") when the headline should be evidence.

### 2. Frameworks as data, not code

`frameworks/courtroom/orchestrator.ts` is: `phase(prosecutor) → phase(defense) →
parallel(jury, vote) → conditional(judge)`. That's a _spec_, not a program. Instead
there are 26 hand-written orchestrators (~12k lines of framework code), each
re-implementing prompt-build → call → regex-parse → print. Correct approach: one engine
interpreting a declarative spec (roles, phases, parallelism, voting rule, output Zod
schema). Framework #27 becomes a 50-line config; hardening applies uniformly to all 26;
community contribution stops being copy-paste engineering.

### 3. A library should never `console.log`

534 console.log calls in the framework layer. Programmatic users and the MCP server
inherit stdout graffiti; `--output json` consumers get noise. Correct approach: a
reporter/event interface — CLI subscribes and renders pretty, MCP streams progress
events, library silent by default. Streaming would have come "for free".

### 4. Structured outputs instead of regex parsing

`parseJSON` greps LLM output for ` ```json ` blocks. Zod schemas already exist — feed
them to provider-native structured output / tool-use modes, plus one validation-feedback
retry ("your response failed schema: … fix it") instead of throwing. Kills a whole class
of fragility.

### 5. Model IDs are the fastest-decaying constants in software

`claude-3-7-sonnet-20250219` is hardcoded in `core/config.ts` and quoted in
ARCHITECTURE.md cost tables. Correct approach: role aliases (`reasoning`, `fast`,
`cheap`) resolved through a small registry, overridable per run. New model drops →
one-line change, not archaeology across 26 configs.

### 6. One package, not 28 workspaces

Each framework has its own `package.json` + `node_modules`, and cli.ts does a
`PKG_ROOT`/`isBundled` path dance to dynamically import them. Buys nothing for internal
modules — subpath exports from a single package deletes the whole problem.

### 7. One test pyramid, not four test systems

`test/core`, `test/frameworks` (e2e, real API), `test/integration` (mock), **and**
`test-suite/` with its own runner and cases. Two tiers suffice: mock (fast, CI) and live
(key-gated, nightly).

### 8. Smaller things

- `cli.ts` is a 1,275-line god file; its `FRAMEWORKS` metadata duplicates info that
  should live in each framework module.
- Documented exit codes 1/3 only fire for `result.verdict.decision`-shaped results, so
  most frameworks always exit 0.
- README has five overlapping framework-selection aids (tier tables, selector table,
  categories, decision tree, Q&A) — pick two.
- Bun-only distribution is an adoption tax.

## B. Punch list to make it awesome (ordered by leverage)

1. **Build the eval harness.** 20–50 ground-truth cases for the 3–5 flagship frameworks
   (`test-suite/cases/` already has 4 seeds). Measure framework vs single-shot baseline.
   Put the numbers in the README. Converts the repo from "cool demo" to "credible tool" —
   and it's the moat; competing multi-agent libs don't show decision-quality lift either.

2. **Actually publish.** STATUS says production-ready, roadmap says unpublished. Make the
   bin Node-compatible (`bun build --target=node` or tsup), verify
   `npx institutional-reasoning courtroom case.json`, cut the release. Right now the
   repo's best state is "almost shipped".

3. **Reporter interface + streaming.** Refactor `console.log` → events. Unlocks: clean
   `--json` mode, MCP progress streaming, and later a `replay run.json` transcript viewer
   (audit logs already capture everything — the viewer is nearly free and would be a
   killer demo on the website).

4. **Composition as the differentiator: `chain`.** `pre-mortem → courtroom → aar`
   pipelines as a first-class runner. "Institutional pipelines" is the thing no competing
   library has and a natural extension of the concept. Pair with an LLM-based router for
   `--which` (currently a static tree).

5. **Cost guardrails surfaced.** Middleware already has budget support — expose
   `--max-cost 0.50` and print an estimated cost on `--dry-run`. For a tool whose runs
   cost 5–15× a single call, this is table stakes for trust.

6. **Provider-native structured outputs + validation retry** (A4) and **model-alias
   registry** (A5).

7. **A gallery of real runs.** 5–10 anonymized transcripts in docs/website — watching a
   jury deliberate a merge decision sells the concept harder than any table.

8. **Hygiene finish-line.** Move `demo*.ts` out of repo root; delete the committed
   `.tgz`; collapse the README's redundant selection sections; fix exit-code parity
   across frameworks; expose the last 6 frameworks via MCP or drop the caveat.

9. **Add a "when NOT to use this" section.** Multi-agent deliberation costs real money
   and latency; saying plainly "for a quick gut-check, a single call is fine" is the kind
   of honesty that makes OSS repos trusted.

---

**One-sentence version:** the engineering is ahead of the evidence — stop adding
frameworks, prove three of them work better than one agent, ship the package, and make
composition the headline feature.

_Suggested starting points: eval harness (B1) or npm publish prep (B2)._
